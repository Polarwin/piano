# Auditing Generated Piano Lessons

This guide defines the publication audit for the **Six Months to Piano**
course. It applies whether a lesson was generated by Kimi, Codex, or another
provider. Generation success is not approval: every lesson must pass file,
notation, audio, curriculum, pedagogical, and provenance checks before it is
treated as reviewed.

## Audit outcomes

Give every lesson one of these outcomes:

- **Pass** — safe to publish without changes.
- **Pass with notes** — usable, with a documented minor issue that does not
  misteach the learner.
- **Revise** — files work, but the content, progression, notation, or audio
  needs correction.
- **Reject and regenerate** — structurally invalid, misleading, corrupted, or
  substantially outside the day's scope.

A lesson must not pass merely because its PDF opens and its MP3 plays.

## Source of truth

Before auditing a day, identify its approved scope:

- Days 1–60: `CURRICULUM.md`
- Days 61–90: `MONTH_3_SUGGESTIONS.md`
- Days 91–180: `MONTHS_4_TO_6_SCOPE.md`
- Configured titles and generation prompts: `make_curriculum.py`
- Reviewed melody notes: `melodies.py`
- Authentic repertoire and licensing: `/srv/files/piano/library/README.md`
- Library course levels: `/srv/files/piano/library/levels.json`

The scope takes priority over generated prose. If the lesson contradicts the
scope, revise the lesson rather than changing the curriculum silently.

## Recommended audit order

Audit in this order so inexpensive failures are found first:

1. Confirm expected files and filenames.
2. Validate the PDF and MP3 technically.
3. Extract and review the lesson text.
4. Inspect the printed notation.
5. Listen to the complete audio while following the score.
6. Check the day's curriculum placement and prior knowledge.
7. Check adult pedagogy, playability, and practice length.
8. Verify named repertoire and licensing.
9. Record the decision and required corrections.

## 1. Coverage and filename audit

Each course day must have exactly one PDF and one MP3. There should be no
orphaned media and no duplicate editions with slightly different titles.

For a single day:

```bash
find /srv/files/piano/lessons -maxdepth 1 \
  \( -name 'Day_95_*.pdf' -o -name 'Day_95_*.mp3' \) -print
```

For a range:

```bash
python3 - <<'PY'
from pathlib import Path

root = Path('/srv/files/piano/lessons')
start, end = 91, 180
errors = []

for day in range(start, end + 1):
    pdfs = list(root.glob(f'Day_{day}_*.pdf'))
    mp3s = list(root.glob(f'Day_{day}_*.mp3'))
    if len(pdfs) != 1 or len(mp3s) != 1:
        errors.append((day, len(pdfs), len(mp3s)))

print('PASS' if not errors else f'FAIL: {errors}')
PY
```

Pass criteria:

- exactly one PDF and one MP3 per expected day
- both use the same basename
- filename day and printed title day agree
- no `.wav`, temporary JSON, zero-byte, or partial output is published

## 2. Technical media validation

Check file type, PDF page count, MP3 duration, and decoder errors:

```bash
file /srv/files/piano/lessons/Day_95_*
mutool info /srv/files/piano/lessons/Day_95_*.pdf
ffprobe -v error -show_entries format=duration \
  -of default=noprint_wrappers=1:nokey=1 \
  /srv/files/piano/lessons/Day_95_*.mp3
ffmpeg -v error -i /srv/files/piano/lessons/Day_95_*.mp3 -f null -
```

Normal targets:

- PDF: two to four pages
- MP3: usually under two minutes
- audio: valid MPEG, no decoder errors, clipping, long accidental silence, or
  abrupt truncation
- PDF: opens without repair warnings and contains every page promised

Longer lessons are not automatically wrong, but their extra length must serve
the musical goal rather than repeat generic advice.

## 3. Text extraction and content review

Extract the text instead of relying only on a visual skim:

```bash
mutool draw -F txt /srv/files/piano/lessons/Day_95_*.pdf > /tmp/day-95.txt
sed -n '1,240p' /tmp/day-95.txt
```

Confirm:

- title is exactly `Day N: Approved Title`
- introduction states a clear, achievable goal
- instructions are warm, concise, and written for an adult learner
- practice steps say what to do, how slowly, and when to stop or simplify
- terminology is correct and explained before it is tested
- no section is filler copied from unrelated lessons
- historical day references match the configured curriculum
- the lesson does not claim that an unsupported feature is shown in notation
- optional creative work is clearly optional

Search for common warning phrases and references:

```bash
rg -n -i 'day [0-9]+|swing|tie|pickup|sixteenth|authentic|original score|\
music library|hands together|must|pain|tension' /tmp/day-95.txt
```

## 4. Curriculum and chronology audit

For each concept in the lesson, answer:

1. Was it taught on or before this day?
2. Is today's difficulty a small step from the previous week?
3. Does the lesson accidentally require a later skill?
4. Does a review day remain lighter than a teaching or recital day?
5. Does the lesson prepare the stated monthly outcome?

Typical chronology failures include:

- testing dotted rhythms before their introduction
- asking for hands-together scales when the scope specifies separate hands
- using an accidental or key without preparing its keyboard geography
- requiring fast sixteenths immediately after teaching subdivision
- treating a recital day as the first day of learning the recital piece
- citing the wrong earlier day for dynamics, articulation, pedal, or rhythm

Check the surrounding sequence, not only the individual PDF. Read at least the
previous two lessons and the next lesson when judging continuity.

## 5. Notation audit

Visually inspect every exercise at normal page size and zoomed in. Confirm:

- correct clefs, time signature, key signature, and barlines
- every measure has the correct duration
- pickups and complementary final measures are genuinely partial
- tied notes join the same pitch and are not attacked again in the audio
- sixteenth and eighth beams show the intended beat grouping
- 6/8 is grouped and explained as two compound beats, not disguised 3/4
- rests occupy the correct amount of time
- accidentals are musically correct and readable
- chord notes appear simultaneously rather than as an accidental broken chord
- fingerings fit the correct hand and do not require an unsafe stretch
- note names, finger numbers, stems, beams, dots, and tie curves do not collide
- system wrapping does not split a phrase or tie misleadingly
- final double bar and page layout are present and legible

### Duration arithmetic

Durations use quarter-note beats:

| Value | Duration |
|---|---:|
| Sixteenth note | `0.25` |
| Eighth note | `0.5` |
| Quarter note | `1` |
| Dotted quarter | `1.5` |
| Half note | `2` |
| Dotted half | `3` |
| Whole note | `4` |

Bar totals are therefore 2 in 2/4, 3 in 3/4, 4 in 4/4, and 3 in 6/8.
For 6/8, the arithmetic equals 3 quarter beats but the musical grouping must
still be two dotted-quarter beats.

## 6. Audio-to-score audit

Listen from beginning to end while pointing to each printed event. Do not audit
the score and audio separately.

Confirm:

- pitches match the notation
- rhythm and bar placement match the notation
- both hands enter and release at the printed moments
- chords sound simultaneously
- rests are audible as silence of the correct length
- tied continuations have one attack, not two
- pickup audio starts immediately and reaches the first full downbeat correctly
- tempo is slow enough for the intended learner
- section gaps do not sound like unexplained missing measures
- dynamics are broadly audible without clipping
- the final note is allowed to decay naturally

For a suspicious tie or pickup, compare the waveform duration with a nearby
untied exercise and inspect the generated lesson again. A PDF-only fix is not
enough when the MP3 remains wrong.

## 7. Adult pedagogy and playability

The learner should be challenged without being trapped. Check that:

- one substantial new idea is the usual maximum for a day
- the stated practice fits roughly 20–30 minutes
- exercises can be divided into one- or two-bar loops
- hand positions and position changes are stated clearly
- large chords and wide reaches have alternatives
- speed is never valued above relaxation, accuracy, and pulse
- pain, persistent tension, or numbness is a stop signal
- self-checks use observable criteria such as steady pulse or four accurate
  repetitions, not vague demands to “master” a piece
- mistakes are treated as information and recovery is practised
- recital lessons permit the score and do not make memorisation compulsory

Reject exercises that are technically valid but musically joyless, needlessly
repetitive, or much harder than the day's prose suggests.

## 8. Fingering and technique audit

Test every printed fingering at a keyboard when possible. At minimum, trace it
with the correct hand and check:

- fingers are numbered 1–5 with thumb as 1
- scale crossings use the approved hand-specific pattern
- repeated notes, substitutions, and position shifts are physically plausible
- black-key fingering does not force unnecessary twisting
- chord fingering matches the displayed pitch order
- left- and right-hand fingerings have not been copied interchangeably
- no instruction encourages locked wrists, raised shoulders, or isolated
  finger force

Any doubtful fingering should be removed or corrected; an absent fingering is
safer than a confidently wrong one.

## 9. Named melody and authentic-score audit

There are three distinct categories and they must not be blurred:

1. **Reviewed course melody** — notes are stored in `melodies.py` and may be
   injected into a generated lesson.
2. **Preparatory course study** — an explicitly shortened or simplified study
   that sits beside an authentic work.
3. **Authentic library score** — the learner must use the existing sourced PDF;
   generated notation may prepare skills but must not claim to reproduce it.

For any named piece:

- verify title, composer, public-domain or licence status
- compare the melody and rhythm with the reviewed source
- confirm the edition is labelled accurately: authentic, simplified, shortened,
  excerpt, or “after” the composer
- preserve the authentic source when publishing a learner edition
- verify that recital lessons link or direct the learner to the correct library
  PDF, MIDI, and MP3
- reject invented notes presented as a famous or authentic composition

Do not infer licensing from a “free download” label. Record the actual source
and licence in the library README.

## 10. Batch audit after generation

After a month or large range is generated:

- verify one PDF and MP3 for every day
- list page counts and MP3 durations
- extract all titles and compare them to the scope
- search all lesson text for incorrect historical references
- sample every new notation feature visually and aurally
- inspect representative early, middle, review, repertoire, and recital days
- confirm difficulty rises gradually and lighter days remain lighter
- confirm no generated recital notation conflicts with an authentic score
- run `git diff --check` before committing source changes

Representative minimum for each 30-day month:

- orientation day
- first day of every new notation feature
- midpoint checkpoint or review
- first repertoire-preparation day
- hardest coordination day
- final review
- recital day

Representative sampling does not replace checking file integrity for every day.

## 11. Recording findings

Use a concise table so corrections can be reproduced:

```markdown
| Day | Result | Severity | Finding | Required action |
|---:|---|---|---|---|
| 95 | Revise | Major | Pickup padded to a full bar | Regenerate after pickup support |
| 96 | Pass | — | Tie curve and single audio attack verified | None |
| 120 | Pass with notes | Minor | MP3 is 124 seconds | Accept; focused recital warm-up |
```

Severity guidance:

- **Critical** — corrupt media, unsafe instruction, source/licence problem
- **Major** — wrong notes, rhythm, meter, fingering, chronology, or false claim
- **Minor** — wording, layout, optional polish, slightly long duration

Record the generator, date, relevant source commit, and whether the lesson was
regenerated or manually corrected.

## 12. Publication checklist

A lesson is ready only when all applicable boxes pass:

- [ ] Exact approved title and day number
- [ ] One valid PDF and one valid MP3
- [ ] Two to four readable pages, unless an exception is justified
- [ ] Audio normally under two minutes, unless an exception is justified
- [ ] Correct measures, meter, key signature, rhythms, rests, and chords
- [ ] Pickup, tie, and sixteenth behaviour verified where used
- [ ] Score and audio agree from start to finish
- [ ] Fingering is correct and physically reasonable
- [ ] Content uses only skills introduced by this day
- [ ] Difficulty and practice time match the scope
- [ ] Adult tone is clear, respectful, and non-repetitive
- [ ] Named repertoire and licensing verified
- [ ] Authentic scores are referenced rather than rewritten
- [ ] Review/creative work is correctly marked optional or light
- [ ] Findings and exceptions are recorded
- [ ] Source changes pass compilation/tests and `git diff --check`

## Regeneration policy

Regenerate when the lesson's structure or musical content is broadly wrong.
Make a focused source correction when the same engine defect affects many
lessons. Do not repeatedly regenerate around an engine limitation: fix the
engine, add a regression test, and then rebuild affected lessons.

Never overwrite a previously reviewed lesson casually. Compare the replacement
side by side, retain the better edition, and document why it changed.
